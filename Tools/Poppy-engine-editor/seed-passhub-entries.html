PoppyEngine · logins only

Three entries that teach Poppy how to handle being asked about a password: how to tell "which accounts do I have" from "what IS the password", how to talk about something she cannot see, and how to put the vault away again. Writes into the editor's Firebase, not into PoppyEngine-core.js, which is generated.

The block shape — the action names and what q means — is not in here. It ships at runtime from JS/poppy/PoppyEngine-passhub.js with the action spec, the same way navigation's 48 destinations do. These entries are the wording: when she should reach for it, and how she should speak about it.
The one rule none of this can bend. Poppy never receives a password. The engine paints it onto the screen and hands her back nothing but the platform name, because action receipts are posted to the model on the next turn. Every entry below is written so that she describes where the answer is, never what it is — if you reword them, keep that.

Matched by name, so a second run updates them rather than creating duplicates. Your other entries are never read or changed.
