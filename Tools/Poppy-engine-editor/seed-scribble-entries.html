📝 SEED SCRIBBLE ENTRIES

PoppyEngine · 21 entries · Project tier + access + devices + history

Every Scribble entry Jen has written, carried across exactly as worded. The guidelines were lifted out of JS/poppy/PoppyEngine-core.js programmatically and checked character for character against it — not retyped, so there is no transcription to have got wrong.

Three entries are new, and they are the only three in the file that were written rather than copied:

Scribble: Access check — for the scribble_access action. It reports the two doors separately: the archive, and the channel to whatever screen is open. One being open while the other is shut is the normal state right now, and a single yes/no would hide exactly that.

Scribble: Devices — read-only, no action block. Which devices have opened Scribble, which are signed in, which are signed out, when each was first and last seen.

Scribble: Access history — read-only. Every unlock, failed attempt, reroll and lock the gate has seen, laid out as a day timeline, because almost everything asked of it is really about sequence: did those failures turn into a success, how fast did they come, what hour was it.

Access check and access history are separated on purpose. One answers “can you get in”, the other “what has happened at the gate”. The word access alone cannot tell them apart, so the history entry fires on a past-tense or failure word instead — history, attempts, failed, locked out, rerolls. “Do you have access to Scribble” therefore reaches only the check.
The devices entry is deliberately fenced against a question it cannot answer. js/scribble-devices.js keeps one row per device — first seen and last seen — and every visit overwrites the one before it. There is no per-visit log anywhere, so “every time the tablet opened Scribble” has no answer. The guidelines say that outright and forbid building a history out of two dates.
Matched by name. A second run updates these 20 and creates nothing new. Every other entry you own — sleep, food, FLO, PassHub, navigation — is never read and never touched.

The category is inherited, not invented. This looks up Project: Create New Project in your database and writes everything under whatever category that one already sits in. Guessing a name would have made a second Scribble category beside the real one.

What is in here: the Project tier — create, pin, rename, view, duplicate, logs, records, general record, bin, archive, merge, description, inquiries, sort & filter, the activity log, logs control, the recent panel — plus access and devices. What is not: anything for modules, sections or document files. Those commands exist on the page but have no vocabulary yet, and they get appended to this same file.

Two of the 18 are duplicates and are included on purpose, because you asked for all of it: Projects: Logs Control carries a logs header over the Sort & Filter body, and Projects: Recent panel (copy) is byte-identical to Projects: Recent panel.
